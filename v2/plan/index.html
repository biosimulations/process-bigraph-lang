    v2 implementation plan¶

    Status: approved scope for the first round, 2026-10-11. See the research notes, the language design and the registry and authoring design.

    Decisions¶

    1. This round delivers the design documents (done: this directory) and a round-trip prototype that reads real documents and *.composite.yaml files into a v2 model, prints canonical .pblang v2 text for review, writes an equivalent document back, and proves equivalence. The Langium v2 grammar and the pblang CLI come in later rounds.
    2. The v2 syntax is tree-shaped and mirrors the document.
    3. Interfaces come from generated .pblang interface files (manifest JSON canonical).
    4. The DSL interoperates both ways with CompositeSpec yaml.
    5. The DSL is a verifiable target layer; end users author with registry- and prompt-driven tools.
    6. The language core stays one-to-one with the document. The higher-level semantics it adds are static and compile away: named and imported interfaces, faces as sorts, param, let, edge literals, adapters, units, and referential-integrity checks. There is no pattern or macro layer this round; coupling schemes and engine selection stay in Python builders or composite generators, and the DSL records their result.

    Reconciled details:

    • Type spelling in the DSL: int, bool, float, string, map<string, V>, list<T>, maybe<T>, overwrite<T>, enum<a, b>, array<float>[3,3] @ "uM", { a: T; b: U }, A | B, raw "…". The compiler maps int → integer, bool → boolean, map<string, V> → map[V]; unknown names are errors.
    • Error codes: family-prefixed numeric codes with a stable slug (W200 wire-type-mismatch); the mnemonic names in the language design are the slugs.
    • emit: emit parquet { … } with { … }; or emit "local:ParquetEmitter" { … };.
    • Interfaces in decompiled text: resolved addresses print import pkg.{Name}; unresolved ones print an inline declaration from _inputs/_outputs and at "…".
    • Parsing this round: the model is the pivot; text is printed and snapshotted. A Lark parser is a stretch step; the Langium grammar remains the long-term source of truth and binds to the same model.
    • Dependencies: no version bump of process-bigraph or bigraph-schema (nothing needed is 1.7-only). bigraph-schema moves to the main dependencies; process-bigraph stays dev-only (the package returns plain dicts); pyyaml and types-PyYAML join the dev group.

    Reader rules¶

    Walk state and schema in parallel, state key order first. Classify each key in order:

    1. Site: _type == "site" → Store(site=Site(sort, default)).
    2. Edge: _type in process/step, or address present, or the schema entry says edge. Kind from state _type → schema _type → interval present → process → priority/_triggers → step → else ValueError naming the path. address from "proto:data", dict, ${x} or site. Consume config, inputs, outputs, interval, priority, _triggers, _inputs/_outputs (→ ports); drop instance and _contract; everything else → extras verbatim. Short name Composite → inner from config.state/config.schema, bridge, interface. A Stepper-style child {address, config} inside config stays a plain struct value (lossless).
    3. Node: a dict with an edge or site descendant, or a struct schema, or a map schema of edges (Node(type=…)).
    4. Store: everything else; typed from the schema when present; schema-only → value=MISSING.

    Saved form is auto-detected (root global_time, dict addresses, _contract): also drop root global_time, take edge _type from the schema entry, ignore the schema's inputs: "wires" entries, parse string _inputs/_outputs, keep fully defaulted config verbatim. Params come only from CompositeSpec parameters; ^\$\{(\w+)\}$ strings become ParamRef, embedded ones ParamRef(template=…), undeclared ones are errors. Imports come from local:!a.b.C addresses (collisions print fully qualified); local:Name prints as Name with no import. Interface declarations are emitted only for edges that carry ports. CompositeSpec metadata (name, description, tags, requires, emitters, global_time_precision) is read; other keys go to extras.

    Printer rules¶

    Order: a header comment naming the source; sorted imports; params; interface declarations in first-use order; composite name "description" { requires {…} options {…} stores and sites, then nodes, then edges, each in source order }; emit …. Two-space indent; a block prints inline when it fits in 100 columns and no nested block broke. Values: ints as ints, floats via repr, true/false/null, JSON-escaped double-quoted strings, lists […], tuples (…) (preserved so v1 parity holds), struct literals when all keys are identifiers else map literals, ${dt}, ? and ?(default). Arrays and nested lists with more than 100 elements and strings longer than 1000 characters are externalized to <snapshot>.assets/<path-slug>.json|txt (JSON {dtype, shape, data} for diffability; ExternalRef keeps a $bundle_ref-compatible key) and printed as array(file("…"), dtype = "float64", shape = [11, 11, 3]) or file("…"); small arrays print inline with an array(…) wrapper. Port overrides print as ports { … }; unknown keys print as extra { … } or schema { … } as explicit "not understood" markers. A saved nested composite with empty inner state prints a // WARNING: inner state lost by Composite.save comment.

    Writer rules¶

    Schema half: Store.type → to_bigraph with the default folded as {"_type": T, "_default": d} (v1's exact shape); untyped stores → no entry; sites → no schema entry (process-bigraph#213); Node → nested dict or {"_type":"map","_value":…}; edges → no schema entry; schema_extras merged back. State half: values; sites via converter.site; edges {"_type", "_inputs"/"_outputs", "address", "config" (omit empty), "inputs"/"outputs" (omit empty), "interval"/"priority"/"_triggers", **extras}; a nested composite → config = {state, schema?, bridge, interface, …}. ParamRef → "${name}"; ExternalRef → loaded through the assets callback. write_composite_spec → {name, description, tags, requires, parameters {type (normalized bycomposite_spec.normalize_type), default, description, choices}, emitters [{address, paths ["a/b"], config?}], schema?, state, global_time_precision?, **extras}; tests dump it with yaml.safe_dump(sort_keys=False) and feed CompositeSpec.from_dict(...).to_document(emit=False).

    Parity target: write_document(read_document(doc)) == doc exactly for every v1 expected template in tests/compiler/generator/ (toy add-floats, test_collections flat/list/map, spatio-flux I/II/III, test_open_values_compile_to_template_sites).

    Normalizer (behaviour verified against the installed versions)¶

    normalize_document(doc, core): in the schema half drop global_time, move edge entries to a side table ({path: {_type, _inputs, _outputs}}), and render other entries with core.render(core.access(entry), defaults=True), falling back to a canonical sorted dict when access raises on an unknown dict-form type (string names pass through); a rendered string containing a top-level | or : is re-accessed to dict form so "x:float|y:float" and {"x":"float","y":"float"} collide. In the state half drop root global_time; render sites with _sort canonicalized; edges become {_type (state or side table), address as "proto:data", _inputs/_outputs canonical (omitted if absent on both), config canonical (omit {}), inputs/outputs canonical wires (str → [str]; omit empty), interval/priority as float, _triggers}; drop instance and _contract; recurse into nested local:Composite config. Values: tuple → list, ndarray → tolist(), numpy scalars → Python, floats compared with math.isclose(rel_tol=1e-9). diff_documents flattens to state/smoldyn/config/dt-style paths and prints -, +, ~ lines (capped at 200), falling back to a unified JSON diff.

    Ignored: key order, tuple vs list, dtype, runtime keys, string vs structured forms of addresses, wires and types, absent vs {} config, default-in-schema vs float{…}, schema edge entries. Not ignored: config values. A stronger realized_equivalent(a, b, core) (tests only) builds Composite from both and compares serialize_state() and serialize_schema() through the same normalizer.

    Status (2026-10-11)¶

    Steps 0–9 are implemented on the v2-design branch: the package, the tests, the corpus (all six entries, the hybrid fixture generated in the viva-pde-particle environment), the snapshots and the print/diff entry point. The snapshots in tests/fixtures/data/v2/snapshots/ are the material for the design review. Observations from printing the corpus that feed back into the design:

    • The hybrid repeats the same grid literal in four places; the let hoisting in the design (section 2.3) is worth doing early, and the Stepper child prints as a plain { address, config } struct until edge literals exist.
    • Multi-line strings (the generated Smoldyn config) must be externalized at a much lower threshold than other text.
    • Reading from a CompositeSpec alone leaves stores untyped (store molecule_counts = {};), which is exactly the W-STORE-UNTYPED case; types will come from interface files (stretch step 10).
    • The saved form of a nested composite reads back with an empty inner composite; the printer flags it.

    Stretch step 10 is also done in a minimal form: process_bigraph_lang/v2/interfaces.py has describe_module (stage A over a Python module: portable address, config_schema, ports obtained with the class standing in for self, dynamic_ports when that fails, the docstring), an InterfaceRegistry with a JSON manifest (pblang-manifest/0), and python -m process_bigraph_lang.v2 describe <module> --manifest m.json --out m.pblang. The printer resolves edge addresses against a registry and prints import module.{Name}; instead of an inline declaration; the spatio-flux and saved-toy snapshots show it, and toy_library.interfaces.pblang is the first generated interface file.

    Stretch step 11 is done too: process_bigraph_lang/v2/parser.py is a Lark LALR grammar for the printed subset (imports, params, meta/options, inline interface declarations, stores, nodes, edges, nested composites with bridges, sites, ports, extra, schema, emit, the array(...)/file(...) value forms, and the type spelling). Every committed snapshot parses back into a model that prints to the same text and writes a document equivalent to the corpus original (tests/v2/test_parser.py), so the round trip now runs from text. The grammar is the executable form of the sketch in the design and the acceptance spec for the Langium v2 grammar. Not covered yet: expressions, replicate, {default} suffixes on types, when / of config.x faces, and hand-written override files for dynamic ports.

    Headers for a real package exist too: tests/fixtures/data/v2/interfaces/ holds the interface files and manifest that python -m process_bigraph_lang.v2 describe generated from viva-pde-particle's classes inside its own environment (the publish-time step). Against them, the hybrid prints with imports, and process_bigraph_lang/v2/check.py (python -m process_bigraph_lang.v2 check doc.json --interfaces m.json) verifies a document statically, with no process code imported: unknown ports (S021), missing or unknown config keys (T121, S022), wires that name no declared store (W211), wire type mismatches against declared store types (W200), paths escaping the root (E110), an interval on a step (T130), unknown components (S020), dynamic ports (I210) and untyped stores (I220). On the hybrid it finds the particle_positions store that nothing declares and the three components whose ports only an instance can tell.

    The checker also does the writer analysis of the registry design: per store, who writes it and with which apply semantics (from the port type, or the store's own overwrite<T>); W220 (info) lists additive writers whose contributions superpose, W221 warns when an overwriting writer sits next to any other writer (order-dependent), and W223 warns when a step publishes an array-typed value with accumulate semantics. emit declarations are checked too: W240 when a path names no declared store (the emitter would record an empty value) and W241 (info) when an emitted store is written by nothing. Units are checked with pint: port units may contain unit variables (?U, ?U/?T) bound per instance from the wired stores, so a solver that works in any consistent unit system is still checked; W201 reports a mismatch with the conversion factor or as incompatible.

    Making the headers static was a change to the wrapped package, not to the tooling: on viva-pde-particle's static-interfaces branch, SmoldynHybrid always declares particle_positions (the emit_positions flag only decides whether the value is produced) and SpatialRecorder became GridRecorder and MeshRecorder with one fixed face each. The regenerated headers have no ... except on Stepper and SplittingCoordinator, the scheduling wrappers whose face is their child's. process_bigraph_lang/v2/graph.py then produces a viewer's wiring graph (nodes with typed ports, stores, edges, nested children) from a document and the headers alone, which is what a loom-style viewer needs to run without a Python environment that has the processes installed.

    Two decisions made while building the parser: the normalizer canonicalizes types from the parsed type tree rather than through bigraph-schema's renderer (the renderer drops custom type names such as positive_float and fails on unknown dict-form types, so the two spellings of one type no longer collided), and /// doc comments are joined with spaces when parsed because the printer wraps them.

    describe-model (process_bigraph_lang/v2/sbml.py, python -m process_bigraph_lang.v2 describe-model x.xml) is the model-side twin of describe: it reads an SBML file with the standard library and writes a model header (time unit, compartments, species as concentrations or amounts, parameters, each with pint-readable units composed from the model's unit definitions, plus reaction/event/rule counts and the SBML level, version and packages). The Caravagna header is snapshotted; see the design's section 5.6 for how per-document composites and per-class templates use it.

    The grammar has model declarations (headers and sorts), store m : Sort = Header | ?; model sites, and the checker admits a header against a sort (G301, units bound across the header) and checks config values that reference a param against the header's config units; the writer expands a filled model site into the model's typed blocks. The Caravagna header parses back and prints the same declaration.

    The Langium v2 grammar exists (dsl/src/language/pblang-v2.langium, language id pblang-v2, files .pbl), coexisting with v1 in the same language server, VS Code extension and CLI. It parses every snapshot with no parse or linking errors (dsl/test/v2/), and process_bigraph_lang/v2/langium.py binds its JSON AST to the same model the Lark grammar builds; tests/v2/test_langium.py requires identical prints from both. Not yet in the Langium side at that point: validators beyond parsing and name resolution, hover and completion, and the cutover of .pblang to v2.

    The checker was then ported to TypeScript (dsl/src/language/v2/{types,headers,units,check,validator}.ts) and registered as a Langium validation of V2Module, so the editor, the browser and the CLI (check --json) share one implementation; the Lark parser and the Python checker were retired, and process_bigraph_lang/v2/langium.py and check.py call cli-native. The compliance suite moved to dsl/test/v2/check.test.ts case for case; the Python tests keep the same expectations through the CLI. lark and pint are no longer dependencies. One semantic change surfaced by the shipped growth-division example: a wire to .. from a root edge is the idiom for "the parent store", which process-bigraph resolves by clamping at the root, so going above the root is W110, a warning, rather than an error.

    Hover and completion followed (dsl/src/language/v2/{resolve,hover,completion}.ts, see the design's section 5.3, "Editor services"), and header files open in the workspace now answer imports in the editor (V2Registry falls back to the index of V2Interface declarations by module).

    Decided 2026-10-12: the Python datamodel is not a public target. First process_bigraph_lang.v2 exposed compile_text / compile_file (text -> parse -> check -> document or CompositeSpec, CompileError on errors) and decompile (document or CompositeSpec -> text) over an internal model; then the model moved: reader, writer, printer and binder are TypeScript (dsl/src/language/v2/{model,json,paths,reader,writer, printer,bind,graph,modelheader,yaml}.ts) behind cli-native compile | decompile | headers | model-header | graph, and the Python package keeps only the wrappers (api.py), describe (introspection), describe-model (SBML as JSON) and the normalizer. model.py, reader.py, writer.py, printer.py, paths.py, values.py and graph.py are gone; types.py stays as the normalizer's and describe's type parser. The snapshot and round-trip tests under tests/v2/ run through the CLI; dsl/test/v2/{roundtrip,model}.test.ts check the same snapshots byte for byte on the TypeScript side (every corpus document prints to its snapshot; every snapshot is a fixpoint; the v1 expected documents write back exactly). The cutover followed: .pblang is the v2 language (.pbl is still accepted), and v1 is gone, the grammar, its validators, the SBML stub command, the Python compiler and parser bridge, the ANTLR grammar and its generated parsers, and their tests. The v1 expected documents live on as tests/fixtures/data/v2/corpus/v1/. The language id pblang-v2 and the V2 rule prefix were then renamed: the language id is pblang, the grammar is pblang.langium (grammar Pblang), its rules are Module, Store, ... and consumers import the generated AST as a namespace (ast.Store) because its names coincide with the object model's.

    Risks¶

    Render quirks (handled by re-render and re-access; covered by tests); local:Name vs local:!path (kept verbatim; the printer only imports ! forms; the writer never rewrites); nested-composite save loss (authoring documents only; negative test); numpy in config and state (tolist plus isclose; array(…) wrapper or sidecar); saved-form config bloat (equality only claimed after normalization); deptry and mypy (no process_bigraph import in the package; yaml test-only); snapshot churn (fixed ordering and repr floats; explicit regeneration flag); prettier reformatting the copied yaml (accepted; noted in the corpus README).

    Out of scope this round¶

    The Langium v2 grammar and ast_model.py changes; the pblang check/compile/decompile/doc/registry CLI beyond the v2 print | diff entry point; manifests for real viva packages; viva-catalog, workbench, viva-superpowers and pbg-template changes; execution-environment work (rest:, git:); upstream asks to process-bigraph and bigraph-schema. These are sequenced in the roadmap of the registry and authoring design.
